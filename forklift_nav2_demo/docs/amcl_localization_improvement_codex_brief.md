# AMCL 定位发散改进 — codex brief

目标：让仿真里行驶（尤其过拐角原地自转、走长直巷道）时 AMCL 不再发散，
从而能在 `lattice_fallback_to_astar: false` 下端到端跑通 `sparse_corner` 等多段路线。

负责分工：codex 实现（主要是 nav2 yaml 参数 + 必要诊断）；assistant 在仿真里实测验证。

## 现象

清洁启动定位在 (-2,-0.5) 正常；一旦开始行驶，map→base_link 位姿**几秒跳十几米**，
停下后锁死在错误位姿（实测 map→odom 修正量 ~7.8m）。这是定位发散，不是规划器/控制器逻辑回归。

## 现状配置（`forklift_nav2_demo/config/forklift_nav2_oru_test_foxy.yaml` 的 `amcl`）

关键缺陷/可疑项：
- `recovery_alpha_fast: 0.0` / `recovery_alpha_slow: 0.0` → **自适应恢复完全关闭**：一旦发散无法注入随机粒子自救。**最大缺陷。**
- `laser_max_range: 100.0`：远超工厂图实际尺寸，max-range/虚假远点会误导似然场。
- `laser_min_range: -1.0`：用扫描自带 min；叉车车体/货叉若在激光 FOV 内会自击，宜设显式下限。
- `alpha1..5: 0.2`：通用值；长车 + 原地自转工况下旋转噪声(alpha1/alpha2)可能不匹配。
- `max_beams: 60`：长直巷道（沿巷道方向存在 aperture 模糊）下偏少。
- `update_min_a: 0.2`：自转时更新偏疏，旋转中纠正不及时。

## 可能根因（按可信度）

1. **恢复关闭** → 任何短暂发散都不可逆（直接导致"锁死在错误位姿"）。
2. **长直巷道 aperture 模糊** → 沿巷道方向漂移，本就需要更多 beam / 更勤更新 / 恢复兜底。
3. **快速原地自转**（本轮新加的 pivot：0.5 rad/s 绕 base_link 旋转）→ 旋转期间里程计运动模型与扫描匹配难协调；
   且控制器按后轴(-0.34)做 pivot 而 gazebo 绕 base_link 转，行驶/里程一致性需核对。

## 诊断（改前先确认，改后再验证）

仿真跑一段含拐角自转的行驶，记录并对齐时间轴：
- `/tf` map→odom 修正量随时间（发散是否在**自转瞬间**突跳，还是在**长直行**中缓慢漂移）；
- `/odom` vs `/amcl_pose`（里程计是否自洽、扫描匹配是否把估计往一个方向拉）；
- 判断发散主要由 自转 还是 巷道直行 触发——决定下面哪几项优先。

## 改进项（优先级从高到低，多为参数）

1. **开启自适应恢复**：`recovery_alpha_slow: 0.001`、`recovery_alpha_fast: 0.1`（标准做法，先做这一项单独验证收益）。
2. **修激光范围**：`laser_max_range` 收到实际图尺寸量级（如 16~25m）；`laser_min_range` 设显式下限（如 0.3~0.5，避开车体/货叉自击）。
3. **更多 beam / 更勤更新**：`max_beams` 提到 ~120；`update_min_a` 降到 ~0.1（自转中更勤纠正）；必要时 `update_min_d` 略降。
4. **运动模型噪声**：依诊断结论微调 `alpha1`（rot→rot）、`alpha2`（trans→rot）（如 0.3~0.4），让自转期间更信扫描。
5. **粒子上限**：发散/恢复期需要多峰表达时，`max_particles` 提到 3000~5000。
6. **核对自转里程一致性**：确认 gazebo `/odom` 如实反映原地自转；若控制器后轴 pivot 与 base_link 旋转造成实际平移，
   该平移必须体现在 odom 里（否则 AMCL 永远对不上）。必要时把 `bridge_pivot_angular_velocity_radps` 由 0.5 降到 0.25 做对比实验。

## 约束

- 只动**仿真定位相关配置**（amcl 段，必要时 sim 桥 pivot 速率参数）；不改规划器/控制器/真车 Curtis 路径。
- 真车用的是不同的激光/里程，本调参面向仿真；如需区分，放在 sim 专用配置或参数默认值里，别污染真车配置。
- 每项改动尽量**单独验证收益**（先只开恢复，再加激光，再调噪声），避免一把梭分不清谁起作用。

## 验收

- 仿真保持 `lattice_fallback_to_astar: false`，跑 `sparse_corner` 全程：
  - map→odom 修正量保持有界（漂移 < ~0.5m，无瞬跳/teleport）；
  - 机器人依次到达三个 waypoint（含 (-0.3,-0.5) 拐角自转）并停稳；
  - 中途若短暂偏差，AMCL 能自行收敛回来（验证恢复生效）。
- 多点连续点目标行驶不再发散。

## 不做

- 不换定位算法（不引入 slam_toolbox / robot_localization 融合）——本轮只把 AMCL 调稳。
- 不改地图本身（除非诊断明确指向 map 与 gazebo 世界不符，另立项）。

---

## 诊断结论（assistant 实测，2026-06-25）

逐项实测后定位到根因：

1. **item 1（开 recovery）不可用**：`recovery_alpha_fast/slow>0` 会让 nav2 Foxy 的 AMCL 启动即段错误
   （exit -11，处理第一帧扫描时崩）。已改回 0.0。
2. **item 2+3（laser 范围 / beams / update_min_a）已应用但未解决发散**：直行正常，**一到拐角原地自转就发散**。
3. **针对性诊断（纯自转，记录 /odom vs /amcl_pose+协方差）结论**：
   - `/odom` 全程正常（平滑、自转后回到合理位置）；
   - AMCL 在旋转中**协方差爆炸**（yaw 方差从 ~0 飙到 >5）后**跳到错误位姿**（一度比里程偏 3.4m），而里程是好的。
   - ⇒ 发散在 **AMCL 滤波/扫描匹配侧，不是里程漂移**。慢转/修里程（item 6）方向错误。

### 据此的修复（优先）

- **调小运动模型噪声**：`alpha1`、`alpha2` 从 0.2 → ~0.05（必要时 alpha3/4 也降到 ~0.1）。
  仿真里程接近 ground-truth，调小后粒子在旋转中贴着里程传播，扫描匹配无法把估计拽到错误峰。
- 次要：核对/修正"控制器按后轴(-0.34) pivot vs 桥按 base_link 旋转"的不一致——纯自转目标实测被执行成
  ~270° 绕圈（里程绕出再绕回），放大了旋转、给 AMCL 更多发散机会。可单独立项。

### 仍不做

- recovery_alpha 保持 0.0（开了就崩）。
